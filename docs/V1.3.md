# SignalPilot V1.3 — Autopilot foundation

## Goal
Move from audit SaaS to an action/monitoring product without pretending that external AI visibility data exists when no provider is configured.

## Added
- Action and ActionEvent models.
- WordPress connector using WordPress Application Passwords.
- Encrypted connector credentials with AES-256-GCM derived from AUTH_SECRET.
- Explicit apply + before snapshot + rollback flow.
- MonitoringRun and MonitoredQuery persistence.
- Scheduled monitoring cron endpoint.
- Provider-neutral AI visibility endpoint boundary.
- Business cockpit page.
- SSRF/public-DNS validation for connector URLs.

## Safety boundary
Scanner-generated actions are proposals. They are not automatically published. Only explicit `wordpress_content` actions containing a content type, post/page ID and patch can be applied. Every application stores a before snapshot and supports rollback for title/content/excerpt/status.

## Visibility provider contract
Set `AI_VISIBILITY_ENDPOINT` and `AI_VISIBILITY_API_KEY`. The endpoint receives `{query, brand, domain}` and should return `{response, brandMentioned, position, citations}`. If absent, monitoring records provider `unconfigured` rather than inventing observations.
